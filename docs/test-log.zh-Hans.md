# XP‑80T 打印测试记录

测试日期为 2026 年 11 月 25 日，加拿大太平洋时间。情境为零售现场更换网络后，需要重新设置 Xprinter XP‑80T（USB／Wi‑Fi）。以下按测试记录中的时间顺序排列，网络地址一栏使用示例值。

## 一、从 USB 建立可控的测试起点

| 时间（PT） | 做了什么 | 看到什么 |
| --- | --- | --- |
| 约 14:35–14:40 | 改用 MacBook，先确认所在的网络、网关，再用 USB 数据线连上 XP‑80T。用 macOS 的 USB 信息查看设备。 | Mac 能识别 `USB Printer Port`，设备识别码为 `0483:5743`。 |
| 约 15:13 | 检查厂商设置工具和 SDK，并用 Python、PyUSB、libusb 检查 USB 接口。 | 找到 bulk IN `0x81`、bulk OUT `0x02`，端点的最大包大小为 64 bytes。 |
| 同一轮 | 厂商工具里有 AT 字符串，因此用简短的纯文本 AT 指令试探。 | 打印机把它打印到纸上，没有返回有效的 AT 回复。结果确认 USB 打印数据通道有反应，但工具中的字符串本身不足以判断设置方法。 |

## 二、写入 Wi‑Fi 设置，然后逐层验证

| 时间（PT） | 做了什么 | 看到什么 |
| --- | --- | --- |
| 约 15:20 | 通过 USB bulk OUT 写入固定 IPv4、子网掩码、网关、SSID 和 WPA2‑PSK／AES 设置。 | 自检页打印出新的设置值，但最初的 Router Status 显示 `Disconnect`。写入成功和实际连上 Wi‑Fi 要分开判断。 |
| 约 15:25–15:26 | 按设置流程重启打印机，给它时间连上路由器，再从 Mac 验证 IP 和端口。 | 这次 ping 测试为 0% 丢包，`nc` 成功连上 TCP `9100`。这两项确认了主机可以访问、打印端口可以建立连接。 |
| 约 15:27 | 拔掉 USB，通过 Wi‑Fi 向 TCP `9100` 发送 ESC/POS 文字和切纸指令。 | 实际出纸，并且自动切纸。这一步验证了从 Mac 到打印机的完整打印路径。 |

记录设置时，可以用 `192.168.50.200/24` 和 `192.168.50.1` 这样的示例表示打印机地址和网关。实际操作时使用现场已预留的可用地址。

## 三、可重复使用的判断顺序

| 遇到的情况 | 下一个能回答问题的测试 |
| --- | --- |
| Mac 找不到 USB 设备 | 查 USB 设备列表、线材和电源 |
| 自检页已显示新设置 | 查路由器连接状态，再从 Mac 测打印机的 IP |
| Ping 通 | 测 TCP 9100 |
| TCP 通 | 拔掉 USB，实际发送测试页并确认出纸、切纸 |
