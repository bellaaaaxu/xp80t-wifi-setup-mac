# XP‑80T 列印測試紀錄

測試日期為 2026 年 11 月 25 日，加拿大太平洋時間。情境為零售現場更換網路後，需要重新設定 Xprinter XP‑80T（USB／Wi‑Fi）。以下以測試紀錄中的時間順序排列，網路位址欄位使用示例。

## 一、從 USB 建立可控的測試起點

| 時間（PT） | 做了什麼 | 看到什麼 |
| --- | --- | --- |
| 約 14:35–14:40 | 改用 MacBook，先確認所在的網路、閘道，再用 USB 資料線接上 XP‑80T。用 macOS 的 USB 資訊查裝置。 | Mac 能辨識 `USB Printer Port`，裝置識別碼為 `0483:5743`。 |
| 約 15:13 | 檢查廠商設定工具和 SDK，並使用 Python、PyUSB、libusb 檢查 USB 介面。 | 找到 bulk IN `0x81`、bulk OUT `0x02`，端點的最大封包大小為 64 bytes。 |
| 同一輪 | 廠商工具裡有 AT 字串，因此用簡短的純文字 AT 指令試探。 | 印表機把它印到紙上，沒有回傳有效的 AT 回覆。結果確認 USB 列印資料通道有動作，但工具中的字串本身不足以判定設定方法。 |

## 二、寫入 Wi‑Fi 設定，然後逐層驗證

| 時間（PT） | 做了什麼 | 看到什麼 |
| --- | --- | --- |
| 約 15:20 | 透過 USB bulk OUT 寫入固定 IPv4、子網路遮罩、閘道、SSID 和 WPA2‑PSK／AES 設定。 | 自檢單印出新的設定值，但最初的 Router Status 顯示 `Disconnect`。寫入成功和實際加入 Wi‑Fi 要分開判斷。 |
| 約 15:25–15:26 | 依設定流程重啟印表機，給它時間連上路由器，再從 Mac 驗證 IP 和連接埠。 | 這次 ping 測試為 0% 丟包，`nc` 成功連上 TCP `9100`。這兩項確認了主機可到達、列印連接埠可建立連線。 |
| 約 15:27 | 拔掉 USB，透過 Wi‑Fi 對 TCP `9100` 送出 ESC/POS 文字和切紙指令。 | 實際出紙，且自動切紙。這一步驗證了 Mac 到印表機的完整列印路徑。 |

記錄設定時，可用例如 `192.168.50.200/24` 和 `192.168.50.1` 示意印表機位址與閘道。操作時使用現場已保留的可用位址。

## 三、可重用的判斷順序

| 遇到的情況 | 下一個能回答問題的測試 |
| --- | --- |
| Mac 找不到 USB 裝置 | 查 USB 裝置清單、線材與電源 |
| 自檢單已顯示新設定 | 查路由器連線狀態，再從 Mac 測印表機的 IP |
| Ping 通 | 測 TCP 9100 |
| TCP 通 | 拔掉 USB，實際送測試頁並確認出紙、切紙 |
